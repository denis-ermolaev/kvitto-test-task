## Ключевые запросы к ассистенту

### 1. GitHub Action для проверок

**Контекст:** нужно проверять код на каждом push, аналогично pre-commit, но без изменения файлов.

**Задача:** предложить реализацию `.github/workflows/deploy.yml`, которая запускает:
- `ruff` — `uv run ruff check` и проверку формата;
- `ty` — `uv run ty check`;
- тесты — `make test_all`.

**Уточнение:** только проверка, без форматирования и правок файлов.

### 2. Функция расчёта графика рассрочки

**Задача:** написать функцию, которая принимает сумму денег и число месяцев и считает график рассрочки. Использовать Google-style docstring.

**Требования:**
- сумма к оплате делится на срок в копейках;
- сумма всех платежей графика ровно равна сумме к оплате;
- лишние копейки уходят в первые платежи;
- даты платежей не нужны.

**Пример:** standard без промокода, рассрочка на 3 месяца.

```python
amount = 1990000
schedule = [663334, 663333, 663333]  # в сумме ровно 1990000
```

### 3. Настройка `conftest.py`

**Контекст:** нужно очищать БД после каждого теста, но не ломать работу `lifespan`, где создаётся `app.state.pg_async_session` и заполняется справочник тарифов.

**Что дал:** структуру фикстур (`db_session`, `clean_database`), `docker-compose.test.yml` с отдельной БД и `Makefile`.

**Что уточнял по ходу:**
- как аннотировать async-фикстуры;
- почему возникает `attached to a different loop`;
- как изолировать dev- и test-контейнеры через имя проекта и порты.

### 4. Финальное код-ревью проекта `make review_project`
**Контекст**: попросил провести финальный чек-лист всего проекта строго по пунктам из AGENT.md, не изменяя файлы в проекте — только читать и анализировать.

**Что дал**: все файлы проекта.

**Что уточнял по ходу**: просил не создавать контейнеры и не запускать make test_all, чтобы ревью не оставляло артефактов. Ревьюер это учёл — pytest только собирал тесты, ruff/ty запускал в режиме проверки.

**Результат**: структурированный чек-лист по пунктам AGENT.md (README, AI_LOG, тесты, соответствие ТЗ, оценка проекта, бонусы) с вердиктами «выполнено / частично / не выполнено» и замечаниями. Итоговая оценка ≈ 103/110. Позволяет быстро проанализировать возможные баги, например, допущенные по невнимательности, например, пропуск создания .env в GitHubActions и т.п.

## Где модель ошиблась и как я это заметил

### 1. Лишние аргументы в GitHub Action

**Что предложила:** запуск инструментов с парой лишних аргументов.

**Как заметил:** я знаком с этими инструментами и понял, что аргументы избыточны.

### 2. Отдельный engine и session_maker в `conftest.py`

**Что предложила:** создавать в `conftest.py` отдельный engine и session_maker для тестов.

**Как заметил:** у меня есть отдельный Docker-контейнер с тестовой БД, поэтому можно переиспользовать `app.state.pg_async_session`, создаваемую в `lifespan`.

**Итог:** решение упростилось — не нужно дублировать настройки движка, а тесты стали ближе к проду.
### 3. Ревью проекта: придирки и нерациональные архитектурные выводы
Предлагает избыточность для тестового задания, по типу использовать для Idempotency-Key уникальный индекс, чтобы не было дублей.
Это нужно фильтровать, чтобы не реализовывать фичи, которые на самом деле не нужны в данный момент.
