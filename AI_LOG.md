### 2–3 ключевых запроса к ассистенту — как ставил задачу и какой контекст давал ?
1) Предложи реализацию GitHub Action .github/workflows/deploy.yml для запуска ruff (uv run ruff check / проверка формата), ty (uv run ty check) для проверки типов и запуск тестов (make test_all), аналогично pre-commit хукам, но без изменения файлов и форматирования - просто проверка
2) Напиши функцию, которая принимая сумму денег и число месяцев считает график рассрочки
Пример: standard без промокода, рассрочка на 3 месяца
amount = 1990000
schedule = [663334, 663333, 663333] # в сумме ровно 1990000
Сумма к оплате делится на срок в копейках. Сумма всех платежей графика ровно
равна сумме к оплате; лишние копейки — в первые платежи. Даты платежей не
нужны.
Используй google style docstring
3) Попросил помочь с conftest.py: нужно, чтобы БД очищалась после каждого теста, но при этом не ломалась работа lifespan (там создаётся app.state.pg_async_session и заполняется справочник тарифов). Дал структуру фикстур (db_session, clean_database), docker-compose.test.yml с отдельной БД и Makefile. По ходу обсуждения уточнял: как аннотировать async-фикстуры, почему возникает attached to a different loop, как изолировать dev- и test-контейнеры через имя проекта и порты.


### Где модель ошиблась или предложила слабое решение и как ты это заметил ?
1) В GitHub Action было пару лишних аргументов при запуске инструментов / Я знаком с инструментами и понял, что эти аргументы избыточны
3) Модель изначально предложила создавать отдельный engine и session_maker в conftest.py для тестов. Я уточнил, что у меня отдельный Docker-контейнер с тестовой БД, и можно переиспользовать app.state.pg_async_session, создаваемую в lifespan. После этого решение упростилось: не нужно дублировать настройки движка, тесты ближе к проду.
